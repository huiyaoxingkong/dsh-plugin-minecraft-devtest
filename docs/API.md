# API reference (generated)

> Generated by `npm run gen:docs` on 2026-11-18 from `index.js`. Do not edit the tool table by hand.

`dsh-plugin-minecraft-devtest` is a DeepSeek Harness (DSH) plugin. It injects 12 model-facing tools;
all server-side work happens locally in the plugin, so the model only receives compact results.

## Tools (12)

| Tool | Purpose |
| --- | --- |
| `mcdt_server` | Start, stop, inspect or read logs of a headless Minecraft server (no game client needed). Jar mode runs "java -jar server.jar nogui"; gradle mode runs "gradlew.bat runServer" (or a custom task). Before start it writes eula.txt and patches server.properties (offline mode, RCON, port), keeping other keys and a backup. |
| `mcdt_command` | Run a Minecraft server console command over RCON and return the server response text. Use for assertions such as "data get block", "execute if block", "scoreboard players get", "datapack list", "time query gametime". |
| `mcdt_bot` | A Mineflayer player bot that replaces the game client for client-free player-level tests: chat, walk, dig, place, craft, use blocks and items, open containers, fight and inspect state. It can only join the test server started by mcdt_server in this session (no arbitrary host/port). Fabric/vanilla/Paper servers accept it directly; modded Forge 1.20.1 test servers need the bundled dedicated bridge mod (mcdt_bridge install). |
| `mcdt_datapack` | Inspect, validate, deploy and reload Minecraft datapacks without a game client. scan/find/validate a pack structure against the expected pack format; deploy copies a pack into the test server world datapacks and reload/list run /reload and /datapack list over RCON. deploy/reload/list only work on the test server started by mcdt_server in this session. |
| `mcdt_bridge` | Manage the dedicated test bridge mod that lets the vanilla-protocol player bot join a modded Forge 1.20.1 test server. The bridge is written for this plugin (no third-party mods) and shipped in vendor/. status scans the server loader/version and reports whether the bridge is installed; install copies the bundled jar into <serverDir>/mods (server must be stopped, restart to load); remove deletes only bridge jars installed by this plugin. |
| `mcdt_test` | Run a deterministic YAML test card (or inline steps) against the headless server and player bot, and return a compact pass/fail report. This is the token-saving path: write many assertions into one card, the plugin executes them locally. Steps: command, bot, datapack, gradle, server, assert, wait, note, snapshot. Stops at the first failure by default. |
| `mcdt_suite` | Run every YAML test card in a directory and return one compact summary (failures only by default). Use this after edits to re-verify a whole test set without spending tokens per case. |
| `mcdt_quickcheck` | One-call deterministic health check for a Minecraft datapack / mod project / server directory: static validation, headless server start, RCON smoke, datapack deploy + reload + datapack list, log error scan, and a player-bot join/chat smoke test. Returns a compact check list so common checks do not need any model round-trips. |
| `mcdt_gradle` | Run any Gradle task in a Minecraft project (build, runGameTestServer, runServer, genSources, ...). Returns exit code, a parsed GameTest/BUILD summary and a trimmed log tail. runGameTestServer is the client-free way to verify Forge/NeoForge mod logic. |
| `mcdt_init` | Generate a starter test-card directory (default <projectDir>/mc-tests) for a datapack or Gradle mod project. The generated card contains only safe, repeatable checks (deploy, reload, datapack list, recipe existence, block loot tables, bot join/state/leave) and TODO notes for behavior that needs hand-written assertions. Pass overwrite=true to replace an existing card. |
| `mcdt_logs` | Read or summarize the log of the test server started by mcdt_server in this session (no arbitrary files): mode=tail returns recent lines, mode=errors returns parsed ERROR/exception lines plus datapack-load problems, version and loader. |
| `mcdt_guide` | Built-in guidance to save round-trips and web research: server setup, datapack format/checks, player-bot usage, test-card syntax, version tables and common error meanings. |

Parameter schemas are registered with DSH and are discoverable by the model automatically.

## Version support

- Server lifecycle: official releases **1.7.10 – 26.3**, 26.4 forward-compatible; Java auto-selected (8/16/17/21/25).
- Datapacks: **1.13+** (1.7.10–1.12.2 clearly unsupported); pack formats are read from the server jar or `lib/versions.js`,
  including 1.21.9+ `min_format`/`max_format` handling.
- Bot: `1.7.x` legacy, `1.8.8–26.1` native Mineflayer, `26.2/26.3` bundled upstream compatibility layer, `26.4` best effort.
- Loaders: Forge/Fabric/NeoForge/Quilt server installs are detected and launched in all supported launch forms.

## Safety boundary

The plugin only ever controls the one test server started by `mcdt_server` in this session.
Bot/command/datapack actions reject arbitrary host/port or externally running servers.
Start any test server with `online-mode=false`; the plugin patches EULA/RCON/whitelist for you.
